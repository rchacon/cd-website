CivicDog is an evolving, production civic-tech product suite: an ETL pipeline that syncs U.S. Congress
members, bills, and roll call votes from the official government API, a REST API that serves it —
including a **semantic search API** that answers natural-language questions about legislation — an app
backend and React web app that make up the core product experience, and a WordPress plugin that puts
the data in front of real site visitors. This section is a deep, honest walkthrough of how it's built — the architecture,
the trade-offs, and the automation — for anyone who wants to see the engineering behind the product.

## The repos

CivicDog is split across five repositories, each with a single responsibility:

| Repo | What it is |
|---|---|
| [`cd-webapp`](https://github.com/rchacon/cd-webapp) | The React web app at [app.civicdog.com](https://app.civicdog.com) — the core product |
| [`cd-platform`](https://github.com/rchacon/cd-platform) | Python monorepo: `cd-etl` (Airflow ETL) + `cd-api` (FastAPI, deployed on Lambda) + `cd-server` (app backend for `cd-webapp`) |
| [`cd-lookup`](https://github.com/rchacon/cd-lookup) | The WordPress plugin that consumes `cd-api` |
| [`cd-infra`](https://github.com/rchacon/cd-infra) | Terraform for every AWS resource this stack runs on |
| [`cd-website`](https://github.com/rchacon/cd-website) | The [civicdog.com](https://civicdog.com) landing page and this docs site |
